Hiring status / pipeline / stages / lead status

2636.0% of RX
Pack: gap (pipeline) · automations adjacent
What the theme is
Pipeline state machine and status vocabularies: stuck/wrong hiring or lead status, stage moves, disposition/reject reasons, ATS↔CRM mismatch.
Phenom knowledge
Not a dedicated phenom-knowledge pack. Automations often trigger on status/field changes (automation-search-service) and can set status via actions — exact CRM status APIs not grounded in current packs.
To reduce feedback %
  • Show each customer which hiring/lead statuses they can use and which moves are allowed — cuts “what statuses exist?” and stuck-pipeline tickets.
  • When ATS and CRM disagree on status, show both values side by side so Support (and the customer) can see the gap immediately.
  • If an automation moved a candidate’s status, let the recruiter see that in the run history — unexplained status changes create SRs.
  • Stop silent auto-reject recipes: require confirmation or a clear warning before candidates are rejected automatically.

Phenom knowledge

Candidate profile data / fields / tags / location / GDPR

46310.6% of RX
Pack: gap (Profile)
What the theme is
Integrity and configurability of the candidate record: wrong/missing fields, tags, location/phone/email, GDPR/purge/privacy, field add/rename failures.
Phenom knowledge
No dedicated CRM Profile pack. Closest: Messaging notes UI (crm-notes-ui; notes-api not cloned). Recruiter Hub/profile services appear on Engineering capability-map but are not in phenom-knowledge routing packs — do not assert internals.
To reduce feedback %

  • Give admins a simpler way to add, rename, and manage custom fields and tags without opening a ticket.
  • Publish clear timelines for GDPR / data-purge requests, and let customers check status themselves instead of chasing Support.
  • Add short in-product help for “how do I change this field?” so those questions never become SRs.

Campaigns / job alerts / subscriptions / spotlights

3708.4% of RX
Pack: messaging
What the theme is
Audience + outbound campaign lifecycle: campaigns not sending/wrong audience, job alerts/subscriptions, spotlights/dynamic lists, talent-pool/nurture language.
Phenom knowledge
Messaging: crm-campaigns-ui (builder), storm-campaign (execution), crm-lists-ui / crm-candidate-lists (lists, opt-in/out), platform CampaignController / CampaignsController. Gateway /ecampaign/* → exact backend module unverified.
To reduce feedback %
  • Before a campaign sends, show who will receive it and why it would fail — so recruiters catch wrong audiences and bad setups themselves.
  • Make spotlights and dynamic lists use the same filters as the list builder — mismatches drive a lot of “wrong people got this” tickets.
  • Let customers control job-alert subscriptions (internal vs external) and see a simple audit of why an alert went out.
  • Give CS and Product a live view of bounce and send failures so chronic delivery problems are fixed before they pile up as tickets.

2455.6% of RX

Phenom knowledge
Messaging: crm-templates-ui (template-page.component.ts), email-facade-service TemplateController, gateway TemplateAPIController. Campaigns pull templates before storm-campaign send.

Screening / interview / scheduling / offer / notifications

3949.0% of RX
Pack: screening + automations (+ scheduling blocked)
What the theme is
Funnel friction across Screening (ODVA/questionnaire), interview/scheduling/calendar, offer letters, and missing recruiter notifications.
Phenom knowledge
Screening (partial): ODVA config/status/notify in crm-video-assessment (VideoAssessmentConfigController, VideoAssessmentStatusController, VANotifyService → Kafka cp_automation_notification). Video capture/AI scoring/X+/Fitscore/Questionnaires not in cloned Screening repos. Scheduling area blocked (no accessible repos). Automations Temporal activities: SEND_ODVA, INITIATE_SCREENING, INVITE_FOR_INTERVIEW. Notify path often lands in Messaging.
To reduce feedback %
  • Fix the path so invites and status changes reliably notify the recruiter — many tickets are “I never got notified.”
  • Ship ready-made automation recipes for “invite to interview” and “send video assessment,” and show a clear history when a recipe fails.
  • Calendar and self-schedule bugs need Scheduling code access first — treat that as a prerequisite before promising product fixes.
  • For questionnaires and assessments, finish Screening knowledge packs before committing to deep engineering work.

Automation not triggering / failing / wrongly triggered

1703.9% of RX
Pack: automations
What the theme is
Recipe match + execute reliability: not firing, wrong fire, failures, screening/invite automations, run-history gaps.
Phenom knowledge
Automations: crm-automations-ui; AutomationController CRUD; automation-search-service match (KafkaConsumer, Lucene+ES, ValidatorService); execute via candidate-automation ActionFactory (24 actions) and/or Temporal activities in crm-automation-service. CRMAutomationUtils shared lib not cloned.
To reduce feedback %
  • Let customers see a simple run history: what triggered, which recipe matched, and what the action did (or why it failed).
  • Let them preview and validate filters before turning a recipe on — fewer “it fired on the wrong people” tickets.
  • Alert when a recipe should have matched but quietly did not — silent misses create mystery SRs.
  • For Support, document which actions run on which engine so debugging is faster and handoffs are clearer.
